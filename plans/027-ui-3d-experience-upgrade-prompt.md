# CityLit experience upgrade — research, plan and reusable agent prompt

## Goal and problem being solved

**Goal:** substantially elevate CityLit’s interface, typography, layout, place-specific 3D dioramas, environmental realism, motion, accessibility, and performance—without sacrificing the app’s existing identity, controls, reliable mobile behavior, PWA/offline characteristics, or rendering speed.

**Problem:** the ambition is clear, but a broad wish list (“Disney/Pixar-level,” realistic water, clouds, buildings, roads, people, wildlife) can lead an implementation agent to overbuild, add redundant effects, replace working systems, or spend polygons and GPU time on detail users cannot perceive. CityLit already contains extensive 3D, UI, animation, quality-tier and performance infrastructure. The work must therefore start with a verified audit, identify the actual gaps, prioritize changes by user impact and risk, and demonstrate improvements with tests and before/after evidence.

The cinematic direction is an _aspiration_, not a promise to reproduce a studio’s proprietary style or an instruction to imitate copyrighted characters. Aim for appealing silhouettes, rich staging, tactile materials, convincing weight, clear acting, and memorable place identity, while retaining CityLit’s own stylized miniature aesthetic.

The graph-backed project audit and existing planning notes indicate that CityLit is already a React 19 + TypeScript 7 PWA using raw Three.js r187, a custom WebGL/WebGPU renderer abstraction, procedural landmark builders, Motion, GLSL/TSL shaders, and an existing visual/performance QA pipeline. Do **not** assume the requested capabilities are absent.

- Day/night palettes and lighting, weather-driven atmosphere, moving foliage/wildlife, dynamic lighting details, and water/cloud shader infrastructure. Relevant modules include `CitylitEngine.ts`, `dioramaKit.ts`, `placesSliceBuilders.ts`, `osmSlice.ts`, `placesClouds.ts`, `water.glsl.ts`, `cloud.glsl.ts`, `siteVisuals.ts`, and renderer modules.

- Quality selection/adaptive rendering, LRU/prewarm behavior, contact-sheet and scene-stat QA, plus unit tests. Existing project commands include `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm qa:capture`, `pnpm qa:stats`, and `pnpm qa:renderers` (check current scripts before relying on a command).

## Suggested execution strategy

1. **Establish truth before design decisions.** Inspect repository status, read `AGENTS.md`, query graphify before the first source search/read (per project rules), consult relevant graph/wiki/plan sections, inspect the current UI in the browser and capture stable scene baselines. Reconcile prior plans with code; mark requested capabilities as present, partial, missing, or broken.
2. **Define a small art-direction and UX target.** Describe the intended mood, hierarchy, palette, readable type scale, spacing system, component states, motion behavior and scene composition. Use the supplied visual references for principles only. Keep the existing CityLit identity and clear controls. Do not redraw the whole app by default.
3. **Prioritize as a sequence of small, reviewable batches.** Start with the highest-confidence, most visible defects (for example actual typography/readability or layout collisions; visibly inaccurate hero landmark features; assets clipping the stand; visibly implausible water; an identified animation discontinuity). Follow with cross-site systems only after one or two representative dioramas prove the approach. Label effort, dependencies, device/backend scope, regression risk and value for each item.
4. **Implement only verified gaps.** Reuse current component, renderer, shader, fit, biome, motion, quality and pooling abstractions. Add no renderer framework, effect library, model importer, remote asset dependency or broad architectural rewrite without measured need and explicit approval. Keep authored scene data deterministic and safe for offline use. Prefer bespoke, source-informed landmark enhancements over generic procedural filler.
5. **Validate function and appearance.** Add focused unit tests for deterministic calculations/geometry contracts and regression tests for behaviors. Capture representative landmarks, day/dusk/night, water/cloud states, clipping/stand boundaries, viewport sizes and both renderer backends. Compare to the same-harness baseline. Report measured deltas, known limitations and failing checks honestly.
6. **Leave the repository cleaner.** Run formatting/lint, type check, tests, production build and relevant renderer/stat/capture QA. Inspect `git diff`; remove only your temporary artifacts; run `graphify update .` after code changes as required by `AGENTS.md`.
